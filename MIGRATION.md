# Перенос существующего бота

Новая установка использует отдельные пути и службу. Установка `url_bot.deb`
не удаляет и не изменяет предыдущую установку. Структура SQLite и названия
настроек сохранены: переносятся пользователи, языки, ссылки, описания,
подписка, статистика, черновики и очередь рассылок.

1. В старом CLI сделайте резервную копию базы и сохраните её вне папки данных.
   Для работающей SQLite используйте SQLite backup API, а не копирование
   одного файла, когда есть несохранённый WAL.
2. Остановите и отключите прежнюю службу. Два процесса с одним токеном
   не должны работать одновременно. Сохраните токен и ID администратора.
3. Установите `url_bot.deb`. Пустая конфигурация не запускает бота.
4. До настройки токена/ID поместите резервную копию в
   `/var/lib/url-bot/bot.sqlite3`. Не заменяйте уже используемую базу без
   отдельного бэкапа. Проверьте целостность SQLite (`PRAGMA integrity_check`).
5. Установите владельца `urlbot:urlbot` и права `0600` для перенесённой базы.
6. Откройте `url-bot` и укажите прежние токен и ID. Служба запустится с
   перенесённой базой. Проверьте ссылки, статистику и очередь рассылок.

Старые URL, подписи и описание из вашей базы намеренно сохраняются. Если они
содержат прежнее название, измените их в **Админ меню**. Переименование проекта
не перезаписывает пользовательские настройки.

При запуске из исходников задайте `DATABASE_PATH` с абсолютным путём к прежней
базе, доступным текущему пользователю. При установке через `install.sh`
используйте пункт импорта базы в `sudo url-bot-admin`.
